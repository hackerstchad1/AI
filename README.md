## 1. Introduction

Avoir son compte GitHub suspendu peut être une catastrophe, surtout si vous utilisez la plateforme pour :
- Héberger vos projets personnels et professionnels
- Contribuer à des projets open source
- Déployer des applications (GitHub Actions, Pages, Packages)
- Gérer votre portfolio et votre réputation de développeur

Ce guide vous explique comment réagir rapidement, contacter GitHub, et maximiser vos chances de récupérer votre compte ou, à défaut, vos données.

---

## 2. Pourquoi GitHub suspend un compte ?

GitHub peut suspendre un compte pour plusieurs raisons. Voici les principales :

### 2.1 Violation des Conditions d’Utilisation (ToS)
- Utilisation de GitHub à des fins illégales
- Hébergement de malware, virus, exploits
- Contenu protégé par des droits d’auteur sans autorisation
- Fraude, phishing, escroquerie

### 2.2 Activité automatisée abusive
- Bots qui spamment des étoiles (stars), forks, issues, pull requests
- Scraping massif de données
- Création de faux comptes

### 2.3 Contenu inapproprié
- Discours haineux, harcèlement
- Contenu pornographique ou violent
- Menaces envers d’autres utilisateurs

### 2.4 Problèmes de sécurité
- Compte compromis (piraté)
- Activité suspecte détectée
- Utilisation de credentials exposés

### 2.5 Non-respect de la DMCA
- Publication de code source volé
- Contournement de protections DRM
- Partage de contenus sous copyright

### 2.6 Paiement ou facturation
- Carte bancaire refusée
- Litige de paiement
- Compte organisation non payé

## 3. Types de suspension

### Suspension temporaire
- Le compte est désactivé pendant une durée limitée
- Vous pouvez généralement contester la décision
- Possible de récupérer le compte après vérification

### Suspension permanente
- Le compte est banni définitivement
- Très difficile à faire annuler
- Nécessite de prouver une erreur de la part de GitHub

### Restriction partielle
- Certaines fonctionnalités sont bloquées (issues, pull requests, Actions)
- Le compte reste visible
- Moins grave qu’une suspension complète

### Shadowban / limitation invisible
- Vos dépôts n’apparaissent plus dans les recherches
- Vos contributions sont moins visibles
- Difficile à détecter sans analyse approfondie

## 4. Premières actions à faire

### Étape 1 : Vérifier le message de suspension

Lorsque vous essayez de vous connecter, GitHub affiche généralement un message indiquant :
- Le type de suspension
- La raison (parfois vague)
- Un lien vers le support

**Notez précisément le message.** Il sera utile pour votre demande de récupération.

### Étape 2 : Ne paniquez pas

Une suspension n’est pas toujours définitive. Restez calme et méthodique.

### Étape 3 : Ne créez pas immédiatement un nouveau compte

Créer un nouveau compte pour contourner une suspension peut aggraver la situation. GitHub peut considérer cela comme une violation supplémentaire.

### Étape 4 : Rassembler les preuves

Avant de contacter le support, préparez :
- Votre adresse email associée au compte
- Votre nom d’utilisateur GitHub
- Les dates approximatives des événements récents
- Tout email reçu de GitHub concernant la suspension
- Des captures d’écran si possible
- L’historique de vos contributions si vous les avez sauvegardées

### Étape 5 : Vérifier vos emails

GitHub envoie généralement un email expliquant la suspension. Cherchez dans :
- Votre boîte de réception
- Vos spams / courriers indésirables
- Vos notifications GitHub

## 5. Contacter le support GitHub

### 5.1 Formulaire officiel de support

🔗 **Lien officiel** : https://support.github.com/contact

Choisissez :
- "Account recovery"
- "Suspended account"
- "Appeal a suspension"

### 5.2 Email du support

Vous pouvez aussi envoyer un email à :
- `support@github.com`

### 5.3 Twitter / X officiel

- `@github`
- `@GitHubSupport`

Les messages publics peuvent parfois accélérer le traitement, mais restez professionnel.

### 5.4 Conseils pour le contact

- Soyez poli et professionnel
- Ne niez pas systématiquement si vous avez commis une erreur
- Expliquez clairement votre situation
- Fournissez toutes les informations demandées
- Ne spammez pas le support avec de multiples tickets

## 6. Modèles de messages

### 6.1 Si vous ne savez pas pourquoi vous êtes suspendu

```
Subject: Account Suspension Appeal - Username: [votre_username]

Hello GitHub Support Team,

My GitHub account [votre_username] was recently suspended, but I am not aware
of any activity that would violate GitHub's Terms of Service or Community
Guidelines.

I use GitHub primarily for [description de votre usage : projets personnels,
open source, travail professionnel, etc.].

Could you please provide me with more details about the reason for the
suspension and what steps I can take to resolve this issue?

I am happy to cooperate and make any necessary corrections.

Thank you for your time and assistance.

Best regards,
[Votre nom]
[Email associé au compte]
```

### 6.2 Si vous pensez que c’est une erreur

```
Subject: Wrongful Account Suspension Appeal - Username: [votre_username]

Dear GitHub Trust & Safety Team,

I believe my account [votre_username] was suspended by mistake. I have
reviewed GitHub's Terms of Service and Community Guidelines, and to the best
of my knowledge, I have not engaged in any prohibited activity.

Recent events that may have triggered a false positive:
- [Exemple : connexion depuis un nouveau pays / nouvel appareil]
- [Exemple : utilisation d'un VPN]
- [Exemple : activité inhabituelle due à un token exposé]

I have already taken the following security measures:
- Changed my password
- Enabled two-factor authentication
- Reviewed my authorized applications and tokens

Please review my case and let me know if you need any additional information
to restore my account.

Sincerely,
[Votre nom]
[Email associé au compte]
```

### 6.3 Si vous reconnaissez une erreur de votre part

```
Subject: Account Suspension Appeal and Acknowledgment - Username: [votre_username]

Hello GitHub Support,

I am writing regarding the suspension of my account [votre_username].

After reviewing the situation, I understand that my actions may have violated
GitHub's Terms of Service, specifically regarding [précisez la violation
supposée].

I sincerely apologize for this mistake. It was not my intention to harm the
platform or its community. I have taken the following corrective actions:
- Removed the problematic content
- Reviewed GitHub's Terms of Service
- Secured my account (changement de mot de passe, 2FA, etc.)

I kindly ask you to consider reinstating my account. I value GitHub as a
platform and I am committed to following the rules going forward.

Thank you for your understanding.

Best regards,
[Votre nom]
[Email associé au compte]
```

### 6.4 Si votre compte a été piraté

```
Subject: Account Compromised and Suspended - Username: [votre_username]

Dear GitHub Security Team,

I believe my account [votre_username] was compromised and used to perform
activities that led to its suspension. I did not authorize these actions.

Indicators of compromise:
- Login from unknown locations or devices
- Unauthorized repositories or commits
- Suspicious applications or tokens
- Emails de sécurité non sollicités

I have already taken the following steps to secure my account:
- Changed my GitHub password
- Enabled two-factor authentication
- Revoked all personal access tokens
- Removed unauthorized OAuth applications
- Scanned my devices for malware

Please help me recover my account and investigate the unauthorized activity.

Thank you,
[Votre nom]
[Email associé au compte]
```

## 7. Si vous avez violé les CGU

### 7.1 Admettre les faits

GitHub apprécie l’honnêteté. Si vous avez enfreint les règles, reconnaissez-le sans chercher à tout nier.

### 7.2 Montrer que vous avez compris

Expliquez ce que vous avez appris et comment vous comptez éviter de recommencer.

### 7.3 Proposer des actions correctives

- Suppression du contenu problématique
- Modification des pratiques de contribution
- Formation aux règles de la plateforme

### 7.4 Ne pas recréer de compte

Attendez la réponse officielle de GitHub. Un nouveau compte peut être considéré comme un contournement de sanction.

## 8. Si c’est une erreur

### 8.1 Vérifiez les faux positifs courants

- Connexion via VPN ou proxy public
- Utilisation d’un nouvel appareil ou d’une nouvelle localisation
- Automatisation légitime (CI/CD, bots de maintenance)
- Token exposé publiquement par inadvertance
- Participation à un dépôt dont le propriétaire a été suspendu

### 8.2 Fournissez des preuves

- Logs de connexion
- Emails de vérification
- Historique des commits
- Captures d’écran
- Rapports d’audit de sécurité

### 8.3 Soyez patient

GitHub reçoit des milliers de demandes. Le délai de réponse peut varier de quelques heures à plusieurs semaines.

## 9. Récupérer vos données

### 9.1 Si vous aviez activé les sauvegardes locales

Vérifiez vos clones locaux de dépôts :
```bash
# Liste des dépôts clonés localement
ls ~/Documents/GitHub/
```

### 9.2 Si vous n’avez pas de sauvegarde

Malheureusement, si le compte est suspendu, vous ne pouvez plus accéder aux dépôts via l’interface web ou l’API. Essayez toutefois :
- De récupérer les forks existants chez d’autres contributeurs
- De demander à vos collaborateurs de vous renvoyer le code
- D’utiliser des archives publiques (Wayback Machine, archive.today)

### 9.3 Exporter avant toute suspension

**Prévention recommandée :**
```bash
# Cloner tous vos dépôts (script à adapter)
for repo in $(gh repo list votre_username --json name -q '.[].name'); do
  gh repo clone votre_username/$repo
done
```

### 9.4 Sauvegarder les issues et pull requests

Utilisez l’outil `gh` ou des scripts Python pour exporter :
- Issues
- Pull requests
- Comments
- Wikis
- Releases

## 10. Prévention

### 10.1 Activez la double authentification (2FA)

```
Settings → Password and authentication → Enable two-factor authentication
```

### 10.2 Utilisez des tokens sécurisés

- Ne partagez jamais vos tokens
- Utilisez des tokens à durée limitée
- Révoquez les tokens inutilisés

### 10.3 Surveillez les accès

```
Settings → Security → Security log
```

### 10.4 Respectez les CGU

Lisez régulièrement les conditions d’utilisation :
- https://docs.github.com/en/site-policy/github-terms/github-terms-of-service
- https://docs.github.com/en/site-policy/github-terms/github-community-guidelines

### 10.5 Faites des sauvegardes régulières

- Clonez vos dépôts importants localement
- Utilisez des miroirs sur GitLab, Bitbucket ou Gitea
- Sauvegardez vos issues et PR

## 12. FAQ

### Q1 : Combien de temps dure une suspension GitHub ?
Ça dépend de la gravité. Une suspension temporaire peut durer de quelques jours à quelques semaines. Une suspension permanente est définitive sauf appel accepté.

### Q2 : Puis-je créer un nouveau compte pendant la suspension ?
Non, c’est déconseillé. GitHub peut considérer cela comme une tentative de contournement et bannir le nouveau compte.

### Q3 : GitHub peut-il supprimer définitivement mon compte ?
Oui, en cas de violation grave ou répétée, GitHub peut supprimer définitivement un compte.

### Q4 : Puis-je récupérer mes repositories après une suppression ?
Si vous aviez des sauvegardes locales ou des forks chez d’autres utilisateurs, oui. Sinon, il est généralement impossible de récupérer les données.

### Q5 : Que faire si le support ne répond pas ?
- Attendez au moins 7 à 14 jours
- Relancez poliment par email
- Essayez le support Twitter/X @GitHubSupport
- Postez sur les forums communautaires

### Q6 : Une suspension affecte-t-elle mes organisations ?
Oui, si vous êtes le seul propriétaire d’une organisation, celle-ci peut devenir orpheline. Prévoyez plusieurs propriétaires.
